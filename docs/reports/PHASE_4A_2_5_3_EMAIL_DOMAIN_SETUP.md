**Project:** COLIN — Campus Living Verified

**Sub-Phase:** Phase 4A.2.5.3 — Transactional Email Integration  
**Domain Target:** `colin.in`

## 1. Domain Authentication Overview

High inbox placement for student verification and password reset emails requires rigorous domain authentication. Modern receiving MTAs (Google Workspace, Gmail, Microsoft 365, Apple Mail, university domains) enforce strict SPF, DKIM, and DMARC alignment. Emails lacking these records are routinely quarantined in spam or rejected at SMTP connection.

The canonical sending domain for COLIN is `colin.in`.

---

## 2. DNS Records Specification

Add the following DNS records to your authoritative nameservers for `colin.in`:

### 2.1 SPF (Sender Policy Framework)
Specifies which IP addresses and mail servers are authorized to send email on behalf of `colin.in`.

| Type | Name / Host | TTL | Value / Data |
|---|---|---|---|
| **TXT** | `@` (or `colin.in.`) | `3600` | `v=spf1 include:sendgrid.net include:spf.mtasv.net -all` |

> **Security Note:** The `-all` mechanism enforces a **Hard Fail**, instructing receiving mail servers to reject messages originating from unauthorized hosts. Never use `+all` or `?all` in production.

---

### 2.2 DKIM (DomainKeys Identified Mail)
Provides cryptographic proof that an email was actually generated by COLIN and has not been altered in transit.

#### SendGrid DKIM Records
| Type | Name / Host | TTL | Value / Target |
|---|---|---|---|
| **CNAME** | `s1._domainkey.colin.in.` | `3600` | `s1.domainkey.u1234567.wl.sendgrid.net.` |
| **CNAME** | `s2._domainkey.colin.in.` | `3600` | `s2.domainkey.u1234567.wl.sendgrid.net.` |

#### Postmark DKIM Records
| Type | Name / Host | TTL | Value / Target |
|---|---|---|---|
| **CNAME** | `pm._domainkey.colin.in.` | `3600` | `pm.mtasv.net.` |

---

### 2.3 DMARC (Domain-based Message Authentication, Reporting & Conformance)
Unifies SPF and DKIM authentication and instructs mailbox providers how to handle unaligned emails.

| Type | Name / Host | TTL | Value / Data |
|---|---|---|---|
| **TXT** | `_dmarc.colin.in.` | `3600` | `v=DMARC1; p=quarantine; pct=100; rua=mailto:dmarc-rua@colin.in; ruf=mailto:dmarc-ruf@colin.in; fo=1; aspf=r; adkim=r` |

#### Recommended Policy Staging:
1. **Week 1–2 (Monitoring):** `p=none` (Log reports only, no delivery interference).
2. **Week 3–4 (Quarantine):** `p=quarantine; pct=100` (Deliver unaligned messages to Spam folder).
3. **Week 5+ (Enforcement):** `p=reject; pct=100` (Reject unaligned messages outright).

---

### 2.4 Custom Return-Path / Mail CNAME
Custom bounce domain ensures 100% SPF domain alignment (DMARC alignment) with `colin.in`:

| Type | Name / Host | TTL | Value / Target |
|---|---|---|---|
| **CNAME** | `bounces.colin.in.` | `3600` | `pm.mtasv.net.` (Postmark) or `sendgrid.net.` (SendGrid) |

## 3. Verification & Diagnostic Commands

Run the following standard diagnostic commands to verify that DNS records have propagated:

### 3.1 Verify SPF Record
```bash
dig +short TXT colin.in | grep "v=spf1"
# Expected output:
# "v=spf1 include:sendgrid.net include:spf.mtasv.net -all"
```

### 3.2 Verify DKIM Records
```bash
dig +short CNAME s1._domainkey.colin.in
dig +short CNAME pm._domainkey.colin.in
```

### 3.3 Verify DMARC Record
```bash
dig +short TXT _dmarc.colin.in
# Expected output:
# "v=DMARC1; p=quarantine; pct=100; rua=mailto:dmarc-rua@colin.in; ruf=mailto:dmarc-ruf@colin.in; fo=1; aspf=r; adkim=r"
```

## 4. Deliverability Safeguards & Spam Rate Policy

1. **Suppression Enforcement:** The application immediately stops sending to addresses recorded in `email_suppressions` (hard bounces and spam complaints).
2. **Spam Complaint Threshold:** Monitor DMARC aggregate reports (`rua`) and Postmark/SendGrid dashboards to maintain spam complaint rates **below 0.05%** (industry hard limit: 0.10%).
3. **Unsubscribe Headers:** While transactional verification and security emails do not require `List-Unsubscribe` headers, marketing notifications added in future phases must implement RFC 8058 one-click unsubscribe headers.
